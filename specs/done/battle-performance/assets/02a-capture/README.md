# Running-origin replay evidence

The actual menu benchmark's first running window replays pixel for pixel at
CSS 1440×900 / DPR 2: all 5,184,000 pixels match. This establishes only the
running-origin prelude, not later motion windows or the complete backend fixture.
The final capture contains 19 presentations and retains 65,180,680 bytes under
the 128 MiB cap, including generated-ground hash scratch and the boundary PNG.
`command-comparison.json` is the numerical gate, and `capture.json.gz` contains
exact semantic commands, static inputs, pose definitions and their hashes. The
boundary PNG is stored separately. Capture is intentionally unsuitable for timing.

The source is generated-seven-heavy-combat v1 / contact-9000-v2. The bounded
prelude records actual public world calls from first presentation through the
running boundary, including settling and render-only presentations. The manifest
records frame count, retained-byte budget, source/boundary benchmark status,
asset identities and actual grass indirect commands. Loaded appearance hashes
cover encoded image/mesh/animation bytes, processed one appearance at a time.

The earlier cold one-frame replay matched assets but lost crowd LOD history.
Capturing prior submissions fixed crowd tiers. Recording renders alone still
missed updates and grass work performed before settle renders. Replaying exact
outer semantic calls in order resolved the remaining grass difference without
changing production rendering. The earlier impression of a large dirt-boundary
shift was disproved by numerical comparison; it was not a defect or a claimed fix.

The isolated canvas probe confirmed immediate submit→toBlob snapshot behavior.
Subsequent battle checks found source immediate/settled images identical or within
three channel-rounding pixels, and repeated replay stable. Final command replay
matched exactly. Generated ground/SDF bytes, camera/environment and GPU indirect
commands also agree. Three's triangle totals and cached CPU grass tier estimates
are explicitly not actual emitted-work counts.

`alias-check.json` records actual Vite-transform checks for both normal and lab
configs: only intended importers receive wrappers, the factory calls the real
world, and replay imports the real world directly. No production renderer or
simulation changes are required by this lab capture seam.
