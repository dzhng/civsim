# Grass runtime ownership

The three candidate runtimes consume the same packed grass records, blade geometry, wind, thinning, circle/wedge policy and shader functions. The shared publication controller owns revision admission and the production CPU residency state machine. Each backend owns its actual buffers, binding groups, pipelines and compute/draw orchestration. No alternative backend calls a raw pipeline as a fallback.

Record publication retains geometry and pipelines. Buffers are reused within capacity; growth stages replacement record and visible-index buffers before publication. Failed admission leaves the previous valid content. The active record count is independent of allocation capacity, so shrinking or clearing records cannot route stale tail records. Callers await preparation before encoding and submit the previous frame before replacing its records. Unchanged revisions do not upload. Readback helpers are numerical-control tools, not frame-loop telemetry.

TypeGPU uses public typed resources and pipeline APIs, plus its public experimental command encoder to batch routing and rendering. Whole owned ArrayBuffer uploads avoid a CPU copy; offset or shared-buffer views are copied into an exact byte span because its buffer write API accepts an ArrayBuffer. The public `d.invariant` helper works at runtime, but the pinned vertex-function declaration excludes its additional attribute; the narrow decorated-vec4 schema assertion bridges that declaration mismatch. Actual generated render shaders contain `@invariant`.

vgpu uses public storage, geometry, compute, draw and Frame APIs. Its compute facade submits reset and route independently, so a visible base/ring field costs four routing submissions before the render Frame. Empty initialization dispatches compile the compute pipelines because no public compile-only method exists. Ordinary ArrayBuffer views upload without a preparation copy; shared-buffer inputs require one. Draw compile-request counters describe library handles, not unique GPU pipeline creations. The public storage object has a destruction method omitted from its declaration; a checked adapter calls that method, without accessing private fields. The borrowed vgpu context owns pipeline/sampler caches, while the grass owner releases its buffers and geometry.

The [frozen control](../../02-raw/grass) keeps the original single-sample comparison criteria and runs actual source routing, growth, empty publication, offset-view restoration and disposal. All three single-sample controls pass. Four-sample reports are deliberately red: covered-pixel differences exceed that gate and native prepass output differs even when beauty and prepass reuse the same routed buffers. Separate rerouting differences are also reported. No threshold was increased for MSAA.

The [field-history control](../../02-raw/grass-residency) exercises both layers through settle, pan, far suppression, overview and terrain replacement. Every backend matches source indirect counts and publication history. Single-sample ports reproduce the raw dense-interior failures (13 coverage pixels); they are not accepted precision exceptions. All three four-sample field controls reproduce the same larger failures, including a large HDR outlier in the interior pan. Source-only four-sample comparisons are not exact either. These components remain ineligible for a full backend comparison until the documented image gates and full-scene temporal checks pass. No performance or final appearance claim follows from this pass.
