# Complete library scene controls

The shared scene control now exercises raw WebGPU, TypeGPU and vgpu against the same Three scene: 15,560 soldiers across all twenty appearances, grass, directional shadows, standards/readouts and tactical overlays. Eight captures cover initial and settled tactical, wide, horizon and actual L3 views at 2880×1800, one sample. Every capture matches source crowd counts; all three runs report no browser/GPU errors and no retained tracked buffers/textures after scene/runtime teardown.

Each backend submits through its own API. The control starts canvas capture immediately after final submission and then awaits library validation and the diagnostic queue drain. These waits and readbacks belong to correctness controls, not the live benchmark. One input recipe and camera tour feed all routes. The control reports each runtime's actual audience counts, including L3 draws.

Strict image identity remains red. Initial tactical source lighting differs substantially, as in earlier native composition controls; settled numerical differences also remain. Independent [TypeGPU](typegpu/visual-review/report.md) and [vgpu](vgpu/visual-review/report.md) image reviews prefer the candidates’ visible initial formation shadows and find the inspected settled views visually matched. Both record severe shared distant label overlap. These reviews do not establish pixel identity or moving-camera behavior. The fixture has no vista/water or terrain replacement, and fixed views cannot establish smooth camera motion, loading reliability, default-shadow readability on the full map, or performance. The candidates remain unrankable pending those applicable gates and actual Menu timing.

The first TypeGPU attempt reached the ten-minute browser wait timeout without a result. Its log is preserved. A subsequent diagnostic run with stage reporting completed all views, as did vgpu and a raw rerun. The cause of the first timeout is unresolved; these attempts are not a controlled startup-speed comparison, and no rendering fix is inferred from the successful repeat. Stage logging and timeout failure reports now make a recurrence diagnosable.

The per-backend reports contain audience data and pixel deltas; their adjacent PNGs are the review surfaces. The shared executable control and runner remain in `apps/battle-perf-lab/src/raw/scene-check.ts` and `verify-scene.mjs`; the backend selector is lab-only. The coordinated build and scoped TypeScript check pass. Existing lifecycle checks pass, and independent static review found no actionable submission/capture-order or resource-accounting defect. No numerical threshold was changed.
