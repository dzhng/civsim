# Terrain underlay library ownership

The two-draw background band has native, TypeGPU and vgpu owners. Each draws the large backdrop before the selected terrain style, uses the shared rectangle data, interpolates focus distance from the vertex stage, and evaluates relief normals in the fragment stage. Roughness, canopy/noise/color policy, depth-disabled opaque coverage and absence of shadow sampling are unchanged. Shader body and height-function extraction prevent candidate policy copies; the original source material remains the independent image oracle.

The owners borrow the canonical camera and environment. Fixed rectangle buffers are updated in place; style switches allocate nothing. TypeGPU eagerly unwraps its buffers/bind groups and compiles typed pipelines. vgpu uses public geometry, buffers, draw and Frame APIs throughout. Its compile operation leaves bindings lazy, so initialization admits the three draws into a private 1-pixel target and then destroys that target. This is one extra initialization submission, not a per-frame update or hidden world warm-up. TypeGPU uses a32-bit index payload; raw/vgpu use16-bit indices. These ownership/initialization costs remain part of the later complete-candidate measurement.

All six final matrices pass the unchanged1/255 HDR gate:48 image cases, maximum absolute error0.001220703125, zero nonfinite values, browser warnings/errors or remaining buffers/textures. Raw extraction images are byte-identical to the previously accepted raw controls. All16 TypeGPU actual images are byte-identical to refreshed raw. vgpu differs only in default/wide-detail (one pixel each) and horizon (five pixels), each by one display code at both sample counts; its other10 pairs are byte-identical. These are reported differences, not a new tolerance.

The control rejects injected second-buffer and bind-group allocation failures, and both library ports also reject actual duplicate-binding GPU validation errors. Each failed component leaves zero scoped resources; rendering the subsequent real owner proves the borrowed camera/environment remain usable. The scope begins after caller-owned lazy resources are admitted, while end-of-control accounting still covers all candidate resources. This distinction prevents mistaking a retained caller-owned uniform for a component leak. Target cleanup is unconditional even when admission rejects. Diagnostics retain the extraction compile error and the earlier accounting failure; neither is an accepted rendering result.

The dedicated `backdrop-check.ts` owns cases and gates; use `backend=raw|typegpu|vgpu` and `samples=1|4`, the backdrop Vite config and `verify-backdrop.mjs`. Set `BACKDROP_CHECK_URL` and a separate `BACKDROP_EVIDENCE_DIR`. Sparse worktrees use the primary public directory, without asset copies. Reports here cover raw extraction; sibling TypeGPU/vgpu backdrop folders hold candidate reports. `provenance.json` pins tested source identity. Raw-control TypeScript and the Vite build pass. Independent source review found the extraction return typo and a target-cleanup exception path; both were fixed before successful hardware validation, with a clean follow-up review.

Fresh independent review of all six differing vgpu pairs, full views and3x crops (including supplemental horizon ground/edge crops), found no convincing A/B difference or added gap, alignment or lighting defect. The critic documented shared sharp patch boundaries, finite horizon silhouette, soft relief and coarse flecks. Those exposed underlay-fixture features are retained source limitations, not hidden by this port; complete-scene review must check whether the real ground/vista cover them. The [full review and crops](../../02-vgpu/backdrop/visual-review/review.md) preserve those observations.

Complete battle composition, dynamic scene replacement, scheduling and performance remain separate gates. This component does not establish a backend winner or a battle-stutter fix.
