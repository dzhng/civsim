# Battle runtime test cutover

Only tests of the removed Three battle runtime are retired. Shared policy tests stay executable. The following replacements run against production CPU owners or the promoted TypeGPU resource owner; the shadow comparison below is explicitly historical and test-only. No browser or snapshot acceptance is claimed by this ledger.

## Pose palette replacement

All seven old `posePalette.test.ts` cases belonged to `SoldierPosePalette` and its Three attribute manager. Its replacement is exercised by **new** `apps/battle-perf-lab/candidates/typegpu/tests/posePaletteAdmission.test.ts` using real TypeGPU over a recording device (no GPU/browser needed), plus existing production policy/admission tests.

| Old test | Previous behavior | Replacement | Why |
|---|---|---|---|
| actual storage binding count rejects before allocating palette resources | Six bindings rejected, requires seven | New “insufficient storage bindings reject before any palette allocation”: zero actual buffers and balanced scopes | Same resource limit at real native owner. **moved** |
| two frozen sources per body fit whenever their output palette fits | Three bodies/two bones, 384-byte output and six snapshots, sparse retention | New “two frozen sources per soldier fit the output limit and retain sparse slots without repeated uploads”: same 384-byte bound, six snapshots/576 uploaded bytes, then zero reuploads and shrink retaining sparse pair | Keeps split-bank bound and reuse guarantee. **moved** |
| impossible work rejects before packing and falsy submission failure drains every admission scope | Reject invalid dispatch; old Three compute promise may reject a falsy value | New constructor/dispatch failure test rejects dispatch before pack callback, retains resource set and leaves zero scopes; constructor allocation failure cleans partial resources | Old Three compute-promise boundary retired; native allocation/dispatch failure tested directly. **moved** |
| optional reserve is bounded without rejecting a fitting request | Three optional reserve respected device bounds | Tight 384-byte native admission above plus shared `PoseUpload` sizing; no Three reserve API is retained | Same fitting case under enforced owner sizing; removed API does not need a compatibility test. **moved** |
| failed bank replacement keeps the previous output and retries exact sources | Three storage replacement rollback and replay | New “failed palette growth retains the admitted output and retries exact sources”: same buffer identity/count/live resources after rejection; retry admits 13 bodies/26 snapshots/1248 bytes then zero repeat bytes | Covers actual lazy TypeGPU allocation rollback. **moved** |
| two draw audiences share pose slots and do not double palette capacity or uploads | Three mesh queue deduplicated main/shadow slots | Existing `typegpuSceneLifecycle.test.ts`: “every update submits pose once; unchanged camera demand and repeat presentation submit none”; native shadow scene checks one crowd union of main and all shadow views | Shared native audience/palette replaces queue helper and Three attributes. **moved** |
| admission failure retires all owned storage once, including after partial submission | Old constructor scopes + Three attribute manager cleanup | New constructor-allocation failure checks zero remaining resources/scopes; native reuse test double-disposes safely and leaves zero live buffers | Native resource lifecycle replaces Three attribute deletion. **moved** |

## Historical numerical oracle

`shadowViewFit.test.ts` and `nativeShadowFrame.test.ts` retain their assertions. Their minimal historical implementation moved to `web/tests/reference/threeShadowRig.ts`, with a local shadow-layer constant and only shared-policy/Three dependencies. No old battle world, crowd, material, terrain, or pose runtime is retained. This module is solely an independent numerical camera comparison.
