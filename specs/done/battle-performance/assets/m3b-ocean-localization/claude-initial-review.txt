## Ruled out by source trace

- **Sky/background, post, readback.** Lake and ocean cases share env `golden`, 768×512, pitch/yaw/fov/aspect, so their sky-background pixels are the same image (sky is direction-only; only `distance` differs). Lake caps at 0.00098 ⇒ the ocean excess is on water-shaded pixels. Raw post is maxAbs 0 across 32 cases; the unpacker (`numericalReadback.ts:78`) is shared by both sides. *Caveat: lake frames occlude the lower band, so this bounds the sky residual only over sky pixels visible in lake frames.*
- **Constant truncation.** `waterShaderBodies`' `f()` (`packages/battle-renderer/src/shaders/water.ts:11`) and three's `_toFloat` (`web/node_modules/three/src/nodes/core/NodeBuilder.js:52`) both emit full-precision JS `toString`. Same doubles in, same literals out.
- **Geometry roughness.** Three returns `float(0)` when the geometry has no `normal` attribute (`getGeometryRoughness.js:6-10`); `createOceanPlaneMesh` sets only position+index, and the raw water passes `0.0` (`shaders/water.ts:64`). Match.
- **DFG.** Raw embeds three 0.185.1's exact `DFGLUT` bytes (`shaders/dfgLut.ts:1`), and r185 uses DFGLUT, not the analytic approx (`PhysicalLightingModel.js:574`).
- **Camera focus.** `cam.focus` = snapshot `x`/`y` = (0,0); `createBattleFrameUniforms().focus` defaults to `Vector2(0,0)` and the control never writes it — so the view-distance normal fades agree. (Had these disagreed, `detail` would swing 0.84→0.18; they don't.)
- **sRGB EOTF, aerial, sky-LUT sampling.** `terrainLinear` (`shaders/terrainNoise.ts:19`) matches three's `sRGBTransferEOTF`; `aerialWgsl` is a term-for-term transcription of `aerialPerspectiveNode` (`photoreal-renderer/src/atmosphere/aerialPerspective.ts:95-157`) off the same `aerialParams`; the sky LUT is Linear/Linear, no mips, clamp (`skyModel.ts:92-94`), matching the raw shared sampler.
- **Sub-pixel reprojection.** A camera/projection mismatch would put |sky−sea| errors on the horizon row (order 0.1–0.5), not 0.0046. Excluded.
- **Ocean branch algebra.** The raw ocean fragment (`shaders/water.ts:51-64`) maps line-for-line onto `createOceanPlaneMesh` (`seaLayer.ts:370-397`): same shore/depth01/turbidity/agitation ramps, same `mix(0.3,1.0,agitation)*mix(NEAR,FAR,fade)`, same `saturate(foam*agitation)`, same albedo mixes. I found no algebraic difference.

## Supported causes (cannot be separated with what's on disk)

All three are ocean-only *amplifiers* of inputs that are already known to be non-bit-exact, which is exactly why lake passes:

1. **IBL/PMREM atlas difference amplified by the low-roughness regime.** Ocean roughness is 0.105 (α = 0.011) vs lake's `max(...,0.3)`; water albedo is dark (deep 0.025/0.095/0.22), so indirect specular off the PMREM dominates, and at the grazing horizon Fresnel → 1 makes the sea a near-mirror of the atlas. The README itself records the raw PMREM as passing its own threshold but explicitly **not exact** ("small permitted half-float differences"). A ~1% atlas difference lands as ~1% output difference here and nowhere in the lake.
2. **f32 phase precision/fusion at ocean scale.** Ocean |p| reaches ~2.4 km vs the lake's ≤181 m; shortest wave k = 2π/6.5 ≈ 0.97 rad/m, so phase reaches ~2300 rad where f32 ULP alone is 2.4e-4 rad. Propagated through `slope` (per-wave scale ≈ 2·k·A·SEA_SWELL_SCALE ≈ 2.9) that is ~3e-4 rad of normal tilt against a GGX lobe half-width α = 0.011 — order-10% swings in D on the lobe flank before tonemapping. Lake is ~3 orders less sensitive (phase ≤175 rad, swell ×0.035, α = 0.09). This is a genuine precision cause, but it must be shown, not assumed.
3. **Not excluded:** a term inside `standardPbr`/`samplePmrem`/`cubeUv` that only bites at low roughness (the mip-level blend is the obvious suspect). I compared `shaders/standardPbr.ts` structurally against three's model but did **not** do a line-by-line diff of `PhysicalLightingModel.js` + `EnvironmentNode`/PMREM mip selection. That is the one implementation-mismatch surface left with an ocean-specific signature.

## Missing discrimination

**Where the residual is.** `compareHdr` (`numericalReadback.ts:37`) records `maxAbs` but not its index, and the report keeps only per-case scalars plus 8-bit clamped RGBA. A sun-glint streak (causes 1–3), a far-horizon haze band (aerial), foam speckles (noise path) and a uniform tint (albedo) are all consistent with the scalars I can see.
