# Vgpu complete-scene checkpoint

The scene borrows a vgpu context and a public Target/Surface; it owns the complete scene resources. Every crowd upload awaits mesh/L3 publication and dispatches pose compute at that draw boundary. Camera-only preparation refreshes billboard metadata, readouts, standards and grass without repeating pose/LOD work. Readout and tactical-line uploads remain separate ordered commands. A repeated render routes grass again but does not replay crowd uploads.

Presentation uses public vgpu Frame submission: grass routing precedes the Frame, then shadow casting, one combined sky/world MSAA pass, and post. Keeping sky/world in one pass is required by the public MSAA target preservation contract. Opaque terrain, crowd, standards, grass and cutout readouts precede transparent vista and tactical overlays. Horizon geometry has a dedicated back-face shadow caster, without terrain receiver bindings. The existing shadow target retains its documented unused RGBA8 attachment cost.

Resize retains the camera buffer and atomically replaces the HDR/depth/post bundle. Same-size calls allocate nothing. Post-off follows the shared source-equivalent output function, including alpha unpremultiplication and repremultiplication. Post construction admits resources before awaiting pipeline compilation, then encodes a cancelled public Frame to materialize lazy bind groups. That preparation advances the post context's frame clock once and creates one temporary 1×1 output target; it submits no render work and performs no GPU queue-completion wait.

One operation gate rejects overlapping uploads, preparation, replacement, resize or rendering. Disposal closes the scene immediately and releases resources after its owned pending promise settles. Constructor failure releases completed owners. Failed terrain staging retains the old generation; a failure adopting already committed terrain into grass/shadow state disposes the scene. Review also considered an injected exception from disposing the old terrain after a swap: pinned destroy callbacks can theoretically propagate errors, but no throwing callback was identified in our valid terrain ownership path. That hypothetical post-swap cleanup ambiguity is recorded, rather than adding another commit-state protocol.

The vgpu scene's final output submission occurs synchronously when `render` is invoked, before its first await. The returned promise covers vgpu validation, not GPU idle. Browser controls may capture the canvas immediately after invocation and wait for GPU completion separately; the live path must not add that control-only wait.

This checkpoint is CPU-verified only. Twenty-eight lab cases pass, including eleven new vgpu frame/terrain/scene cases. Source/test typechecks pass; a read-only review's staged frame cleanup finding has a [negative guard](cleanup-negative.txt) and a passing fix that releases every resource and preserves the original error. No browser or GPU run was performed for this checkpoint. The shared actual scene route owns upcoming numerical, lifecycle and visual checks; existing component reports do not establish full-scene parity, default-shadow quality, temporal stability or performance eligibility.
