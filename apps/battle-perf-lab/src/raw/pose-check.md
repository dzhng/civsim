# Candidate pose compute

The TypeGPU and vgpu adapters run the existing authored pose kernel. Shared CPU packing owns clip descriptors, frozen-source identity, masked composition metadata and snapshot-bank placement. Each candidate owns buffers, bindings and compute pipelines; neither calls the raw GPU adapter. The shared WGSL extraction changes function packaging only, preserving the source equations and endpoint behavior.

Callers await each `upload` before issuing another upload, reading the output binding or dispatching. Growth admits replacement buffers before committing their sizes and retiring the previous generation. Stable uploads do not await GPU error scopes. Both snapshot banks are repopulated when capacity changes; retained sources otherwise avoid repeat uploads. The returned palette storage is borrowed by mesh draws. Dispose the adapter only after its caller stops encoding work.

TypeGPU exposes its typed palette buffer and render bind group, and encodes compute into the caller's public command encoder. vgpu exposes its public core buffer and uses public `compute.dispatch`, which submits a separate command buffer per active rig. The caller orders those dispatches before render Frames on the same queue. Those extra submissions are a candidate cost, not hidden behind raw encoding. Readback is a control operation, not part of normal rendering.

The control reuses the committed Blender human/mounted fixtures and existing CPU pose/matrix evaluators. The matrix threshold remains `1e-5`. It covers clip and frozen interpolation, exact transition endpoints, masked rider endpoints and blending, frozen upper-to-base composition, growth, sparse retained slots, replacement, empty upload and a 65-instance retry. Scoped invalid allocation injection proves rejection leaves the previous palette output and committed size/count intact, followed by a healthy retry. Actual native buffer tracking requires zero live buffers after disposal while the borrowed device remains alive.

Both candidate reports pass all 30 recorded checks. Maximum matrix error is `7.152557373046875e-7`; both record zero GPU/browser errors or warnings and zero retained buffers. The reports were captured with Chrome and the repository hardware launch flags. Their `GPUAdapterInfo` serialized as an empty object, so they do not provide a durable adapter identity; no performance inference is made. Eight focused CPU tests and the control typecheck/build pass.

Independent review found incorrect TypeGPU string-entry construction and layout resource resolution, plus missing asynchronous growth admission. All were fixed before the successful hardware controls; the injected-failure control exercises the growth fix. This is pose-compute evidence only. Mesh beauty/shadow composition, material mip preparation and full renderer/motion eligibility remain separate work.

Run the `pose.vite.config.mts` control server on port 5198, then invoke `src/raw/verify-pose.mjs` with `POSE_BACKEND=typegpu` or `POSE_BACKEND=vgpu` from the lab's repository root (full path `apps/battle-perf-lab/src/raw/verify-pose.mjs`). `POSE_CHECK_URL` overrides the control URL. Reports live under the spec's corresponding `assets/02-typegpu/pose.json` and `assets/02-vgpu/pose.json`.
