The candidate uses vgpu-owned buffers, geometry, material textures, mip pipelines, pose compute and beauty/shadow draws. CPU audience packing and WGSL equations share the native component's owners. Base vertex/index buffers are shared between the two audience geometries through public borrowed-buffer descriptors; each audience owns its instance stream. Uint32 indices preserve order while ensuring odd triangle counts obey the four-byte upload requirement. vgpu's geometry upload does not pad uint16 indices itself.

Public compute dispatch submits once per active rig; the caller follows those submissions with its render Frame on the same queue. This extra submission cost is retained in candidate accounting. Draws accept separate beauty/shadow camera buffers. The environment occupies group 3 alongside camera 0, palette 1 and material 2. Default environment consumers retain group 2.

The pinned Target factory requires a color attachment and draw requires a fragment entry. The shadow control therefore uses a one-sample RGBA8 auxiliary attachment and a trivial fragment with color writes disabled. The extra attachment consumes four bytes per shadow pixel, and the extra fragment stage is an explicit API cost. Actual depth writes still come from the authored, posed shadow audience. There is no private pipeline access or raw rendering fallback. The world must account for this cost when composing and timing shadows.
