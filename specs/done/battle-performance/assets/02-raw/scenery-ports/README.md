# Scenery component ports

TypeGPU and vgpu own the existing battle-tree and rock geometry, instance buffers, immutable leaf atlas and mip preparation, beauty and directional caster draws. The native vertex and leaf-color algorithms were extracted without changing their math. The shared authored prop registry and placement packing remain the audience/geometry owners. The actual Three fixture is shared across all backends, with six prop kinds and the same camera, lighting, depth and post chain.

Twelve enabled/disabled-shadow, 1x/4x matrices complete with zero GPU errors, console warnings, nonfinite outputs or live candidate textures after disposal. Alpha matches Three exactly in every captured frame. Strict maximum-channel image diagnostics remain red; no threshold was relaxed. Cold source shadow-direction and initial HDR changes remain visible. Later4x native/typed HDR repeats include a0.0001220703125 difference; vgpu has the same magnitude on its first repeat. No warm-up was added to hide this behavior.

`pixel-comparisons.json` compares every PNG to both Three and the raw candidate. In the shadowed4x tactical repeat, TypeGPU differs from raw at nine display pixels (one exceeds one code, maximum25), and vgpu at two pixels (both one code). At the horizon, TypeGPU differs from raw at three pixels and vgpu at15, all one code. Against Three, the same tactical cases retain eight/nine pixels above one code, and each horizon case retains five; these are exploratory diagnostics, not a new acceptance gate. A tactical4x actual/source pair was inspected during this pass; fresh independent visual review remains pending.

The source's current shadow override ignores atlas opacity and casts full leaf cards, using vertex alpha only. Beauty preserves atlas cutout, then writes alpha1 for surviving opaque fragments. These source behaviors are retained explicitly. TypeGPU cannot emit an empty fragment output with the pinned public API: it produces an invalid empty WGSL struct. Its depth-only caster therefore forwards rasterized fragment depth through the public fragDepth builtin while preserving the vertex-alpha discard. This can affect early-depth optimization and belongs in candidate complexity/performance accounting. TypeGPU also uses ordinary clip output because its public typed API lacks invariant annotation; raw/vgpu preserve their existing invariant output. vgpu retains its already recorded unused shadow color attachment cost. No candidate constructs a raw GPU pipeline as fallback.

Packed RGBA upload now uses the same immutable input contract as native preparation. TypeGPU uses its exact byte-offset upload boundary; vgpu uses public queue.writeTexture for texel transfer, with allocation, pipelines and mip encoding owned by vgpu. The packed-mip control covers nonzero subarray offsets, odd dimensions and one-pixel axes in both color spaces. All16 cases and88 mip comparisons are byte-identical to native, with zero errors/warnings/live textures; see `02-native-mips/packed-rgba/report.json`.

Independent review found a pending-growth disposal race. Both ports now track pending allocations and reject replacement after disposal. Actual GPU lifecycle controls grow65 instances, cancel during the asynchronous growth boundary, and verify rejection with zero remaining buffers; a new owner then grows, clears and restores the six source props before its frame check. Their reports are under each port's `lifecycle/`. The follow-up source review accepted this fix and the public depth passthrough. TypeScript, production control build and five image-upload tests pass.

This remains component parity work. It does not establish full-world eligibility, fix the reported battle stutter, improve the source art, or measure performance. Grass, water, vistas, complete live replay and broad caster/motion coverage remain separate gates.

Reproduce with the frame Vite config and the common frame verifier, choosing `raw`, `typegpu` or `vgpu`, samples1/4, and omitting `&shadows` for disabled mode. Add `&scenery-growth` for the actual lifecycle control. The packed-mip control uses `mip-check.html?packed` and `verify-mip.mjs` with `MIP_EVIDENCE_DIR` set to a separate report directory. Build configs retain `copyPublicDir:false`.
