# Native frame lifecycle

Resize publishes one complete attachment/post bundle after GPU error-scope admission. The camera buffer, layout and bind group retain their identity. Until publication, callers may render the old size; a concurrent resize rejects explicitly. Disposal prevents a pending replacement from publishing. Callers must reacquire `hdr`/its views after a successful resize, and await resize before sizing the presentation target. A same-size request allocates nothing and compiles no pipelines. Actual size changes temporarily retain both bundles and rebuild the size-dependent bloom pipelines; this is preparation cost, not a performance win.

The synchronous constructor releases partial allocations if construction throws. As with other native constructors, its caller owns asynchronous GPU initialization admission. Resize owns its own admission and closes all scopes before awaiting, without waiting for GPU queue completion. The latest copied camera, observer and grade are republished at the new physical dimensions.

Post off bypasses bloom and grading, but retains source output semantics. Pinned Three's direct `renderer.render` uses a linear HDR intermediate and an output pass. That pass clamps alpha, unpremultiplies, applies exposure/AgX/sRGB, then premultiplies again. The new bypass follows that order. The existing enabled-post shader remains unchanged and its current comparison contract uses opaque scene input.

[Post results](post.json) retain the previous 72 backend cases and add eight native direct-output cases with an alpha ramp, four presets and changed exposure/grade. Every case has zero numerical difference and no warnings/errors. [The negative alpha report](post-alpha-negative.json) preserves the initial incorrect bypass: maximum error 0.874512 before source alpha ordering was implemented. The source control uses public `setOutputRenderTarget`; a regular offscreen render target would incorrectly omit the output conversion.

[Lifecycle results](lifecycle.json) compare failed-resize retained output and resized output against a fresh frame at both sample counts. The fixture renders procedural geometry with the real environment, checks nonempty RGB, stable camera bindings, same-size pipeline retention, partial-allocation cleanup and final zero live textures/buffers. This is numerical/lifecycle evidence, not a full battle visual or performance gate. An initial empty-draw 4x probe produced a zero resolved image; equality of two empty images was rejected as evidence and the accepted control includes actual geometry. Empty-scene resolve behavior remains outside this component claim.

Eight CPU tests cover all partial post allocation failures, nested frame cleanup, rejected admission, concurrent resize/disposal, retry, retained identity and latest camera/grade publication. Replacing the fixed post constructor with the committed predecessor made both cleanup guards fail (one and five leaked resources); restoring the fix returns all eight tests green.
