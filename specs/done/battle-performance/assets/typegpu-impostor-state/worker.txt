## Behaviour

The TypeGPU billboard layer now publishes **six camera-independent floats per soldier** (world x/y, facing, faction, elevation, living) and derives the drawable record in the vertex stage from those plus **one 48-byte view block**. `crowdAudience.refreshCamera` writes that block per layer and nothing else — identical cost at 1 soldier and at 5 000. Public audience API is unchanged; `packImpostors` is untouched and remains the independent oracle.

Preserved: appearance anchors, tile decisions, corpse fade, size floor, terrain elevation, canonical colours, the quad/UV/surface WGSL bodies, and the clip/depth contract.

## Typed boundary

`impostorDerivation.ts` is **actual `'use gpu'` TypeScript**, not a WGSL string in a typed wrapper: `deriveImpostorRecord(ImpostorState, ImpostorViewBlock) -> ImpostorRecord`, built from typed `foldSign / tileDirection / scanNeighbourhood / exhaustiveTile / impostorTile`. It reads **no binding** — the view arrives as an argument — so the identical function compiles into the vertex stage, into the diagnostic compute stage, and runs directly in JS where a test calls it. Tile directions are evaluated in closed form for the layer's grid, so there is no baked table, no dynamic-indexed array, and the atlas anchor/span are compile-time constants. `tests/impostorDerivation.test.ts` carries the `@ts-expect-error` gate (verified live: deleting one directive makes `tsc -p tests/tsconfig.json` exit 2).

## Ownership decisions worth your audit

- **`layer.update(source, view)` was kept** as a composite that publishes state + view and returns the CPU oracle record. `apps/battle-perf-lab/src/impostorControlBackend.ts` is out of my scope and requires that signature, and its `packingEqual` gate against Three would otherwise silently lose meaning. No frame path calls it; the audience uses `updateState`/`setView`.
- **`apps/battle-perf-lab/tests/crowdAudience.test.ts` was edited** — it parameterises over typegpu+vgpu and asserted `layer.update(group, camera)`. The vgpu arm keeps its exact assertions; the typegpu arm now asserts the stronger thing (two camera moves → two `setView` calls, zero republished soldiers).
- **Tile-index verdict, not a tolerance.** A differing tile fails unless the two cells were baked from a *bit-identical* direction (an even grid folds corners onto interior cells) or the direction is equidistant within a declared band. The 6x4 grid has **zero duplicate cells** and agrees outright on all 520 probes — that's the unconditional arm.
- **4th near-copy of the playwright runner** (`verify-impostor-records.mjs` alongside `verify.mjs`/`verify-sky.mjs`/`verify-colors.mjs`). I did not consolidate: it would rewrite two hardware scripts whose evidence I cannot re-run. Flagging rather than doing it.

## Hardware risks — unresolved, root-owned

1. **The shader's own arithmetic is unmeasured.** The JS run is f32 *storage* with f64 arithmetic; WGSL's guaranteed sin/cos bound is 2⁻¹¹, which could perturb the local direction by up to √2·2⁻¹¹ and flip a tile near a cell edge. The harness declares exactly that band before comparing and reports dot margins; only hardware can say how far reality is from the bound.
2. **Exact bisectors are genuinely ambiguous.** 81 of 118 bisector probes flip tile on the 8×8 grid already at f32 storage, all at |dot margin| < 1e-15. The harness accepts co-optimal picks there and fails anything outside the band.
3. **Nonfinite inputs are out of contract.** A ±Inf eye/position makes `i32(NaN)` implementation-defined on GPU; the CPU oracle's `clampIndex(NaN)` is equally undefined. Not guarded — guarding would diverge from the oracle.
4. **Vertex-attribute shape changed** (5 attributes over a 24-byte stride). Compiled fine against the recording device; real pipeline validation is a hardware first.

Run when you have the GPU slot: start the lab dev server with the candidate config, then `node apps/battle-perf-lab/candidates/typegpu/verify-impostor-records.mjs`. Two dispatches per atlas; the second writes the view block alone and requires every record to become the new camera's.

**No timing or net-performance claim is made.**
