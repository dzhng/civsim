# Native HDR scene composition

This integration control draws authored infantry, playable ground and physical sky through one reverse-Z color/depth frame and the existing grade/bloom chain. The independent source uses PhotorealWorld, PhotorealCrowd, createGroundMesh and BattlePostChain. It deliberately excludes grass, impostors, scenery, cues and shadows, so it is not a complete backend or a performance result.

Six cases at each sample count cover tactical and horizon cameras, bloom toggles, and an identical tactical repeat. Both hardware runs have no GPU/page errors. The exploratory one-code image gate remains red; four-sample horizon output is within0.000977, while tactical and one-sample cases retain isolated larger differences. Reports keep cold and repeated presentations separately.

A first one-sample native scene changes783 display pixels on its next identical draw, while the source repeat is exact. The native HDR itself changes; pose-buffer readback remains byte-identical, and waiting for initialization submissions does not remove the change. Native albedo, mapped-normal and roughness diagnostic shaders each repeat exactly, but those are different programs and cannot prove which part of beauty caused the change. No dummy warm-up or numeric waiver conceals it. Four-sample repeated HDR is exact. This remains an explicit temporal-fidelity diagnostic for later whole-scene testing.

Fresh unprimed review found the paired images visually equivalent at normal scale, with natural row occlusion and no obvious missing soldiers, depth reversal or sky/ground failure. It found no perceptible movement in the one-sample repeat despite its numerical differences. Shared limitations include weak grounding without shadows and the finite test-plane boundary. Tactical bloom is visually inactive here; the separate bright-HDR post control owns bloom activation coverage. These stills do not establish animation continuity, camera smoothness or final battlefield grounding.

Run the dedicated frame.vite.config.mts and verify-frame.mjs with FRAME_CHECK_URL and FRAME_EVIDENCE_DIR. Default is one sample; ?samples=4 adds the multisample integration check. Optional pose-probe, native-material and settle-init modes are investigation tools, not parity configurations. Typecheck/build and independent static ownership review pass; broader lifecycle and complete-world acceptance remain open.
