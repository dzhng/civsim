# Production model review consumers

CPU/code checkpoint only. Final catalog capture, framing inspection, exact repeat
and fresh visual critique remain pending; no portrait, sheet or film was blessed
by this checkpoint.

The existing card, sheet and animation commands now share one capture boundary to
the production model workbench. Appearance identity comes from the registry;
actual role bindings come from each loaded manifest. The raw renderer diagnostic
itself is untouched. Synthetic frame states, placeholder clip names and duplicated
roster tables no longer drive these consumers.

Cards retain their existing pixel dimensions and every consumed filename,
including the artillery alias. Four appearance-state portraits extend the existing
manifest without replacing its keys. A fixed crop copies source pixels unchanged;
it does not erase bronze or cloth because they resemble terrain. Public copies are
written only after the montage gate passes. Sheets sample the applicable authored
action (release when present, otherwise melee); absent optional actions are not
invented. Films use actual clip duration/loop metadata, with terminal death holds
derived from the captured endpoint. GIF quantization and centisecond/player timing
remain review-only limitations; exact chronological PNG sheets own regression.

## CPU review and changed-test ledger

The focused Node tests are new, not re-pinned assertions:

- Crop: the previous RGB field classifier erases bronze/green-cloth samples;
  the unchanged-pixel crop preserves their exact RGBA bytes. Reintroduced old
  classifier fails the regression.
- Motion: exported loop phases exclude the duplicate seam; a nonloop includes its
  terminal endpoint, with delay derived from duration rather than invented frame
  states.
- Binding: differently named exported clips resolve through manifest roles;
  absent optional actions are inapplicable, missing required clips fail.
- Consumer names: every existing card URL agrees with the registry-derived name,
  including the explicit legacy crew alias.
- Static/applicability: zero-duration holds remain valid, and a release-only or
  no-action appearance does not demand melee. Reinstating the positive-duration
  hold restriction fails the regression.

Independent technical review identified the latter two applicability/hold issues;
both are fixed. Adjacent raw red/green output records the discriminating tests.
No simulation, model source, renderer, new dependency or presentation schema was
changed. The shared capture module replaces three independent browser lifecycles,
crop/montage implementations and pose-name mappings.

## Integration obligations

Use the complete canonical catalog for final captures. Framing is provisional
until the actual images are inspected; do not infer readability from CPU tests.
Run the existing package commands with the pinned SwiftShader path, review the
new images, then run an immediate unchanged-source repeat. The CPU card `--check`
will deliberately reject the old incomplete manifest until the new portraits
exist. Remove obsolete unbound shoot GIFs only as part of that reviewed artifact
refresh; no old sources are deleted by the driver migration.

Decisions were delegated by the parent: one shared production capture owner,
registry/manifest identity, preserved old card URLs, pixel-preserving crops and
full descriptor coverage. Sampling eight intervals per clip is bounded review
coverage, not a new game cadence. Root owns global spec status and final admission.
