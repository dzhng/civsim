## Choices you may want to audit

1. **Tests went into the existing lifecycle file, not a new one.** A second file would need a verbatim copy of the ~35-line typegpu mock; one mock owner beat one file per topic.
2. **`installed` reads the texture's `destroyed` flag, not `this.disposed`.** Raw mirrors its own `disposed` field. The typed resource already answers for itself, which is the more truthful reading and a genuine TypeGPU-side difference — but it does mean the two owners derive the same field differently.
3. **`requestedBytes` keeps a literal `4` bytes/sample** beside a format that now comes from the policy, matching raw. Commented as tied to `GPU_DEPTH_FORMAT` being `depth32float` (documented as having no fallback). Deriving it would need a format→bytes map, which the contract rules out as speculative machinery.
4. **Left the ~12 lines of duplication with `RawBattleFrame.depthStats` alone.** Consolidating means editing `worldDepth.ts` and the product raw frame — out of scope, and a shared helper used by one caller would be a parallel abstraction, not a fix.
5. **Pre-existing `oxfmt` long-import line and `oxlint` triple-slash warning left untouched** — both fail identically at HEAD.
