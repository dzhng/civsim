# Crowd audience composition

The shared publication policy owns main/shadow LOD history, plural-view shadow union and per-class L3 grouping. Only a successful complete upload advances history. Failed uploads cannot draw, and later retries use the previous successful history. Empty publications clear retained groups and history length. Every catalog appearance requires a prepared atlas before resource construction, even when its current population is zero.

Raw, TypeGPU and vgpu keep separate mesh/pose, atlas and submission owners. The library audiences call their existing public mesh and impostor APIs; they never call raw rendering. TypeGPU consumes its typed camera/pass and encodes pose work into the supplied encoder. Vgpu consumes its core camera buffer and FramePass and uses the existing public compute scheduling. Both accept a distinct shadow camera; vgpu also forwards a main-camera override to the impostor draw through public `draw.set`.

`refreshCamera` repacks only the retained L3 groups using the new billboard camera. It performs no mesh upload, pose compute, visibility planning or history publication. It requires a successful upload, including an empty initialization upload if camera preparation precedes the first crowd draw. A failed or pending upload cannot be revived by camera refresh.

The asynchronous library uploads reject concurrency. Disposal makes the audience unavailable immediately, but the owned upload finishes before its resources are released. That same promise settles only after cleanup; there is no detached finalizer. When both upload and cleanup fail, the aggregate preserves the original upload error. Input objects must remain stable until upload settles. Retained L3 placement/living inputs are shallow snapshots: one instance object per selected L3 soldier, plus two small playback/base objects only for a corpse with a playback weight. Poses, samples and assets are never deep-copied. This is added allocation cost per crowd upload, not per camera refresh; JavaScript object byte size is engine-dependent. Source setCamera still reads borrowed instance XY for view metadata, and normal callers recycle objects at the next crowd draw. The snapshots preserve this ordered live/replay contract, not arbitrary mutation behavior of the source.

CPU verification has 21 passing cases: seven raw and fourteen library cases cover grouping, shadow union, growth/empty hysteresis, failed publication, camera-only refresh, concurrency, deferred disposal and construction failure. A reviewed vgpu camera-forwarding defect is pinned by a [negative guard result](camera-forwarding-negative.txt), then restored green. A second [negative result](refresh-input-negative.txt) pins stable uploaded placement/corpse weight when the caller recycles objects. Lab tests have a separate config/typecheck so production web compilation does not acquire lab-only library resolution. Dependencies remain owned by web/package.json.

This is a CPU-verified composition handoff, not GPU verification. The existing component GPU reports do not establish this new combined audience's full-scene correctness or timing. Joint scene controls are still required. Lower-level TypeGPU/vgpu impostor growth retains its existing destructive, synchronous resource replacement; the audience blocks failed publications but does not claim transactional GPU admission for that existing path. No source visual policy, simulation, backend selection or quality gate changed.
