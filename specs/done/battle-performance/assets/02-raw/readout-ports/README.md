# Readout library ownership

TypeGPU and vgpu consume the same authored Canvas atlas, packed chip layout, camera packing and shader algorithms as the corrected native component. The GPU owners remain separate so their allocation, upload, encoding and submission costs stay visible. Depth testing/writes remain disabled, surviving cutout alpha remains opaque, and no styling or placement policy changes.

An upload publishes a complete resource set only after admission. A retained spare instance-buffer set protects the previous visible frame from a partial write; successful uploads exchange active and spare sets. Failed staging may discard the spare, but preserves the committed atlas, instance data and counters. Disposal also owns pending resources. The control injects failures at initial buffer/sampler/bind-group allocation, atlas replacement and the second instance write, then verifies actual old-frame rendering and cleanup. It additionally disposes during pending growth. These are new failure regressions, not relaxed image thresholds.

TypeGPU explicitly materializes lazy buffers, samplers and bind groups through public `unwrap`, and draws through its public typed command encoder. vgpu owns buffers, textures, geometry, pipelines and Frame encoding; only authored Canvas texel transfer uses the public native queue because the pinned library has no equivalent upload helper. vgpu pipeline compilation does not admit lazy bind groups. A one-instance draw into an owned private 1-pixel target admits those bindings before publication; the extra submission is counted in `admissionSubmissions`. A zero-instance variant emitted a Chrome warning and is retained under diagnostics. This is resource admission, not hidden warming of the measured world frame. Both ports report retained instance-buffer bytes and real upload bytes. These costs still need measurement in the complete candidate.

The refreshed raw controls and both ports pass every unchanged 1/255 HDR comparison at both sample counts: 54 cases, zero nonfinite values, warnings, device errors or remaining textures. Candidate actual PNGs are byte-identical to matching refreshed raw actual PNGs. The largest HDR differences from Three remain the existing raw values: growth1x 0.003173828125, growth4x 0.002197265625; rotation 0.000732421875. Failed atlas/instance writes preserve an exact repeated frame. Initial failure and interrupted growth checks finish with zero tracked buffers and textures. No simulation or existing test threshold changed.

The independent source/raw visual review found no visible pair regression and improved growth/shrink compared with the broken source atlas; these port images are byte-identical to those raw outputs. Broader motion, complete battle composition, font/DPR portability, throughput and backend ranking remain outside this component result.

Use the dedicated readout Vite config and common `verify-frame.mjs`, setting `FRAME_CHECK_URL` and `FRAME_EVIDENCE_DIR` to isolated outputs. The sparse task config points to the primary public directory without copying assets. Reports in this folder are the raw extraction regression; sibling TypeGPU/vgpu readout folders hold the candidate reports. `provenance.json` identifies the tested sources and pins. Focused CPU layout tests, raw-control TypeScript and the Vite build pass. Independent source review caught incomplete initial admission and non-atomic writes; the follow-up review found those paths resolved before the successful hardware runs.
