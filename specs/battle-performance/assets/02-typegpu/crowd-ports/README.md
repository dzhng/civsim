# TypeGPU mesh crowd

The candidate owns typed pose buffers and compute pipelines, mesh/index/instance storage, material textures and mip preparation, and indexed beauty/shadow pipelines. CPU audience packing and shader equations are shared with the native component. One rig palette is reused by all its tiers and by both audiences. A shadow-only soldier still receives a palette slot, including a far soldier whose beauty is drawn separately as an impostor.

The caller awaits upload, encodes pose preparation and draws into one public command encoder, then submits it once. Each draw accepts an independent camera binding so beauty and shadow views do not overwrite one buffer's values before submission. Resources borrowed from the world remain alive after crowd disposal. Index storage is normalized to uint32. The typed vertex entry uses ordinary clip position: the pinned public IO type rejects invariant position, and these distinct-view beauty/shadow passes have no equal-depth dependency. Grass's separate prepass requirement is unchanged.

The eight-case source control and its pixel thresholds remain unchanged. One/four-sample reports retain all strict color failures; exact coverage, finite output and clean GPU/browser/resource-lifetime results are separate facts. The source/native investigation documents derivative-sensitive primitive boundaries in the [raw crowd evidence](../../02-raw/crowd/README.md). No aggregate metric turns a strict red report green.

Each case's first image remains the comparison image. The identical repeat measures HDR values directly and does not hide an initial frame. The case order begins at far-mesh; a later full-pose repeat does not prove a fresh full-first pipeline is stable. A separate 257-instance growth and empty-upload draw checks both audiences and clear output. This is component evidence; fresh visual critique, full-scene motion, directional-shadow receiving, and performance ranking remain integration gates.

The control adapter uses the public experimental typed command-encoder API. `createCommandEncoder` takes a descriptor, not an existing encoder: the driver creates the typed owner and lends its public unwrapped encoder to typed pose preparation. Passing a native encoder as a descriptor would silently leave pose commands unsubmitted. Source review and compile smokes also corrected deferred layout-resource access, explicit output-struct construction and flat integer interpolation before final controls.
