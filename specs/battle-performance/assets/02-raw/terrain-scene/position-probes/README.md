# Grazing apron position constraint probe

Two serialized1x runs changed one diagnostic variable each from the committed terrain scene. Removing all source/native caster geometry while retaining the shadow-enabled light/receiver graph left the persistent grazing-apron difference unchanged (max0.105712890625, RMSE0.004267244835). This rejects the shadow-sampling attribution; “shadowed apron” described its location, not its cause.

The second run kept casters and changed only the existing RawBattleTerrain `invariantPosition` argument to false for the terrain-scene ground/horizon/vista owners. Both horizon captures then fell to max0.0009765625/RMSE0.0000561584. Other warm cases stayed within0.001220703125. The source's initial-shadow discrepancy remained0.16259765625 and is preserved; no warm-up or tolerance change was used. Both runs retained exact failed/pending replacement images and finished without device errors, warnings or live resources.

The resulting correction uses ordinary vertex positions only for the terrain scene, which has no same-view equal-depth prepass. It leaves grass's required invariant and unrelated control defaults untouched. The paired experiment establishes that the unnecessary invariant-position constraint caused this measured divergence in the composed grazing scene. It does not identify a particular compiler's lowering or claim a performance gain. The4x confirmation also reduces horizon/repeat to0.0009765625; its two pre-existing ordinary-view water pixels and initial source-shadow discrepancy remain strict reds. Fresh visual findings are recorded with the confirmation.
