# Authored battle material adoption

Authored battle maps have physical tint and height but no generated gameplay slope descriptor. The renderer previously used that absence to skip shared rock response entirely. Visual slope thresholds now fall back to the existing neutral terrain profile while explicit generated thresholds retain priority. Authored rock/scree footprints retain their existing softened source color and turf exclusion, while exposed-face coverage derives from geometry; generated descriptors retain classified-tint coverage. The physical grid, descriptor, source normals, terrain recipes and battle handoff are not rewritten.

The same shader factory serves playable ground and vista. There is no additional terrain generator, palette or fallback material. The default slope thresholds have one owner in the neutral material profile, also consumed by campaign.

The initial audit suspected dropped generated ground-cover character: the frontend forwards the descriptor cover to audio but not terrain. Deeper inspection found both current wasm descriptor producers emit only `green-grass`. That omission cannot change present generated-map character, so no speculative cover input was added. Revisit only when an actual producer emits another cover.

Battle already consumes shared scenery models and the neutral drawing layer. Its existing forest placement uses source-cell membership, physical clearings, water exclusions and rendered slope. Those fixes are retained rather than implemented a second time.

Browser material control: the old shader differs by 55,787 pixels between absent and equivalent explicit slope descriptors; the fallback makes them identical. All four existing material snapshots remain exactly unchanged, with no GPU/page errors. TypeScript and all 489 CPU tests pass. Independent Codex review found no actionable defects; it did not verify browser rendering. The material ramp now checks authored-null and equivalent explicit slope input produce identical pixels, with source height/normals/tint unchanged. The authored A/C scene uses the production terrain and scenery with blades/crowds hidden to isolate the rock-ground response; it keeps ground-cover metadata and null gameplay slope descriptors observable. Close full-grass output on unchanged parent code reached valid terrain state without GPU errors, then timed out during the existing 30-second screenshot limit. That limit is not relaxed; full battle composition remains unverified. Initial overview framing was discarded because the rock patches were too small to judge.

This is a bounded adoption checkpoint. Whole battle landscape acceptance, generated highland/woodland/coastal composition, water/environment integration and final performance gates remain open in slice 13 and its dependencies.

Final isolated A/C captures repeat at zero differing pixels and no GPU/page errors. Compared with parent, only 5 pixels in A and 2 in C differ, consistent with roundoff from the additional normal path: these are preservation controls, not a claimed visual improvement. The changing steep-face contract is proved by the material ramp. The semantic ramp also proves authored tint2 leaves existing ground treatment intact while generated exposed-rock tint still changes 412,669 pixels.

The first direct-tint fallback was rejected because it painted dark jagged footprints; see [rejected candidate](rejected-footprint/README.md). TypeScript and all 489 tests were rerun on the final version. Final independent code review found no terrain defects; its sole finding concerned the temporary dependency symlink, which was removed after stopping the dev server. Fresh image critique judges the A/C pairs visually equivalent, supporting preservation rather than a grounding improvement. It still sees weak rock contact cues, cloudy ground transitions and subdued relief; these remain scenery/environment and composed-landscape acceptance work. No new seam, halo or jagged boundary is evident. The bounded semantic fallback is accepted; full battle visual and performance acceptance remains open.
