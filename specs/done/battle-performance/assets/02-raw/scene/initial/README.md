# Assembled native scene diagnostic

This run combines the full twenty-appearance catalog and 15,560 seated soldiers with terrain, grass, standards, readouts, ground cues, attack triangles, projectile effects, directional shadows and post. It uses a generated 400×400 m terrain at 2880×1800 physical pixels. It is a bounded composition control, not the actual Menu battle, the user's original save or a performance result.

All six recorded presentations match source soldier, main-view, shadow-only and pending-impostor counts. No GPU/browser errors were reported; all tracked native buffers/textures were released. None of these cameras selected L3, so this run does not yet prove the audience owner's actual impostor draw path. Water/vista and integrated resize/settings/terrain-replacement coverage also remain separate gates.

The initial tactical image has 870,896 changed pixels; the settled tactical image has 30,911. Wide and horizon have 16,298 and 17,563 respectively. Exact image equivalence is not established. Initialization uses live sampling rather than recorded grass publications; cold differences cannot be attributed solely to a renderer from this run. Source terrain sampling starts after both runtimes finish resource creation. Images and their stats are captured together before awaiting the other renderer, and both perform a settlement presentation followed by an explicit capture presentation.

[Fresh visual review](visual-review/review.md) uses A=Three source and B=native. It identifies weaker initial source formation shadows/highlights, with the conspicuous difference gone after settlement. It finds no concrete one-sided content loss in settled pairs. Shared label collisions, clipped near formations and abrupt test-terrain boundaries limit what can be judged. Static agreement does not prove smooth motion or readable default shadows on the much larger real battle map.

The machine-readable record is [report.json](report.json). This evidence precedes the terrain ordinary-position correction and the additional far-LOD diagnostic. Actual recorded command/publication replay and the live Menu benchmark remain required before backend selection.
