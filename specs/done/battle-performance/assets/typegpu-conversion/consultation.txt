## What's already shared (the leverage — don't re-port it)

`packages/battle-renderer/src/*.ts` (non-`world/`) is renderer-agnostic and **already consumed by the TypeGPU candidate**: `shadowData.ts`, `crowdData.ts`, `crowdAudienceHistory.ts`, `grassData.ts`, `impostorData.ts`, `waterData.ts`, `backdropData.ts`, `overlayStaging.ts`, `terrainScenePreparation.ts`, `frameCamera.ts`, `sceneCamera.ts`, `crowdFrustum.ts`, `readoutCamera.ts`, `gpuAdmission.ts`, `gpuScope.ts`, plus every `src/shaders/*.ts`. The post-promotion capability work landed largely *there* (`shadowData.ts` +321, `shaders/shadow.ts` +102, `crowdAudienceHistory.ts`, `sceneTypes.ts`, `types.ts`), so it transfers for free.

Only `src/world/*.ts` + `battleScene.ts` + `frame.ts` are raw-WebGPU encoders needing a TypeGPU twin. **Two modules are new since the candidate and it imports neither**: `src/worldDepth.ts` and `src/identity.ts`. That is the concrete "don't lose the fixes" risk — not a wholesale restore problem, an import-gap problem.

**Target layout:** new `packages/battle-renderer/src/tg/`, sibling of `world/`, importing the same shared modules. `world/` stays in place and becomes lab-only at M9 cleanup; no selector, no facade.

## TypeGPU 0.12.5 — what is actually unstable (local proof)

Installed: `web/node_modules/typegpu/package.json:3` = `0.12.5`.

- **Module-level `tgpu['~unstable']` is a no-op concern.** `tgpuUnstable.d.ts:16–42` is *entirely* `@deprecated This feature is now stable` re-exports of `tgpu.fn / computeFn / vertexFn / fragmentFn / vertexLayout / slot / lazy / const / comptime / accessor / privateVar / workgroupVar`. All are stable top-level (`index.d.ts:7–27`). Zero module-level unstable dependency.
- **Root `'~unstable'` = `Pick<ExperimentalTgpuRoot, 'createCommandEncoder' | 'createComparisonSampler' | 'createGuardedComputePipeline' | 'createRenderBundleEncoder' | 'createSampler' | 'createTexture' | 'nameRegistrySetting' | 'shaderGeneratorClass' | 'pipe' | 'with'>`** (`core/root/rootTypes.d.ts:427`). Of those, `createTexture` (`:377`), `createSampler` (`:378`), `createComparisonSampler` (`:379`), `with`/`pipe` are **also on stable `TgpuRoot`**, and the `~unstable` copies carry `@deprecated Use root.X instead` (`:433, :473, :476`). Only `createCommandEncoder` (`:451`), `createRenderBundleEncoder` (`:472`) and `createGuardedComputePipeline` have no stable equivalent.
- **The candidate touches exactly one of them**, at 5 sites: `root["~unstable"].createCommandEncoder()` — `candidates/typegpu/frame.ts:138`, `imageTexture.ts:70`, `pmrem.ts:114`, `terrain.ts:348`, and a type position at `shadow.ts:100`.
- **Current public interop can avoid it entirely.** `pipeline.with(encoder: GPUCommandEncoder)` and `.with(pass: GPURenderPassEncoder)` are stable overloads — `core/pipeline/renderPipeline.d.ts:89–90` and `core/pipeline/computePipeline.d.ts:55–56`. A raw `device.createCommandEncoder()` owned by the frame (matching `world/frame.ts:172`) drives every typed pipeline.
- **Cost of avoiding it, stated:** `withPerformanceCallback` / `withTimestampWrites` deferral does not fire on an adopted raw encoder — `core/pipeline/timeable.d.ts:31` *"Returns false when the encoder is one we cannot defer work to, meaning the callback never fires"*, and `commandEncoder.d.ts:8` *"A caller-owned raw encoder, so submission is out of our hands and no work can be deferred."* Acceptable here: `src/gpuScope.ts` + the lab's `nativeGpuTelemetry.ts` already measure raw passes and must not depend on library deferral.
- **Also do not use:** `unstable_names`, `unstable_minify`, `unstable_shaderGeneratorClass`, `unstable_logOptions` on `initFromDevice` (`core/root/init.d.ts:63–82`). Default `'strict'` names are what the committed hardware evidence was captured under.

## Type-safety boundary — schemas/bindings vs shader authoring

**Real today, enforced by `tsc`:** `d.struct` / `d.arrayOf` layouts, `$usage` flags, `tgpu.bindGroupLayout` + `root.createBindGroup` key/resource matching, `tgpu.vertexLayout` + `attribs` against a `vertexFn.In`, `FragmentOutToColorAttachment` attachment shape, and texture format/`sampleCount`/dimension generics (`CreateTextureOptions`, `rootTypes.d.ts:233`).

**Not real today in this codebase:** shader bodies. `TgpuFnShell` has three overloads (`core/function/tgpuFn.d.ts:23`): JS function (TGSL, checked), **`(implementation: string)` (unchecked)**, and tagged template (unchecked). The candidate's 46 `'use gpu'` sites are entry-point wrappers; every substantive body is a WGSL string from `packages/battle-renderer/src/shaders/*.ts` fed through the string overload — e.g. `candidates/typegpu/sky.ts:32–35` (`tgpu.fn([d.vec2f], d.vec3f)(equirectDirectionWgsl)`) and `shadow.ts:26–34`, where `.$uses({ shadowPcf })` injects a dependency by *name* inside a string. Struct field names, uniform members and globals like `LUMA` in `shaders/post.ts:14` are unchecked: renaming a `d.struct` field compiles and fails at WGSL resolution or GPU validation, never at `tsc`.

**Recommendation:** none of the three passes below converts a shader body to TGSL. Those bodies are byte-shared with the raw reference and with the Three oracle (`candidates/raw-post`, `verify-sky.mjs`) — rewriting them destroys the only equivalence gate available. Convert bodies to TGSL **one at a time, after that body's GPU gate is green and pinned**, retaining the WGSL string as the oracle. Say this in the spec so "TypeGPU = type safety" is not overclaimed: passes 1–3 buy typed *bindings*, not typed *shaders*.

## Pass 1 (first, bounded, independently verifiable) — single root / frame / depth owner

The candidate's blocking structural defect: **22 `tgpu.initFromDevice({ device })` calls across 20 files** (`overlay.ts:42`, `post.ts:59`, `posePalette.ts:31`, `water.ts:24`, `crowd.ts:64`, `backdrop.ts:29`, `terrain.ts:67`, `imageTexture.ts:22`, `standards.ts:57`, `scenery.ts:40`, `sky.ts:23`, `impostor.ts:52`, `pmrem.ts:33`, `shadow.ts:38`, `grass.ts:87`, `environment.ts:74`, `readout.ts:29`, `frame.ts:45`, `preflight.ts:17,73`). `init.d.ts:111` — *"Creates a root from the given device"* — is not memoized, so that is 20 resolution namespaces, 20 pipeline caches and 20 `destroy()` lifetimes on one device. That contradicts the single-owner requirement and must be fixed before any component port, or every later pass inherits it.

New files, all under `packages/battle-renderer/src/tg/`:

| File | Owns | Source |
| --- | --- | --- |
| `root.ts` | The **one** `tgpu.initFromDevice` per device; scene creates, scene destroys; components take a borrowed `TgpuRoot` parameter | new |
| `camera.ts` | `Camera` `d.struct` + `cameraLayout.$idx(0)` | `candidates/typegpu/camera.ts` verbatim |
| `bindIndices.ts` | One explicit `$idx` map for every world layout | new — see gap below |
| `depth.ts` | TypeGPU pipeline `depthStencil` + attachment adapters over `battleWorldDepth` / `battleDepthBypass` / `BATTLE_DEPTH_ATTACHMENT` | `src/worldDepth.ts` (candidate never imported it) |
| `identity.ts` | `TG_BATTLE_SUBSTRATE = "typegpu-webgpu"`, `TG_BATTLE_PROJECTION = "camera3d"` | mirrors `src/identity.ts` |
| `frame.ts` | attachments, camera buffer/group, encode, `depthStats()` | `candidates/typegpu/frame.ts` + fixes below |

`tg/frame.ts` deltas against the candidate, each a real regression if skipped:
1. Borrowed root — delete `initFromDevice` at `frame.ts:45` and `root.destroy()` at `:200`.
2. Depth contract — replace the hardcoded `depthClearValue: 0`, `depthLoadOp: "clear"` at `frame.ts:167–170` and the literal `"depth32float"` at `:238` with `tg/depth.ts`. Today they happen to agree; `worldDepth.ts` exists precisely so they can't silently diverge.
3. Port `depthStats()` (`world/frame.ts:211–228`) and publish `identity` — `battleDepthReversed()`, `requestedBytes`, `depthDescriptor`. This is the `d3147865` / `fa397c1c` "report the actually installed scene" capability the candidate predates.
4. Resize admission barrier — candidate `frame.ts:80–105` has no `beginGpuAdmission` / `await finish()` around replacement; raw `world/frame.ts:117–140` does, and rejects concurrent resizes with the old bundle still live. Adopt the raw shape.
5. Encoder policy — `encode(encoder: GPUCommandEncoder, …)`; delete `createCommandEncoder()` (`:136–139`), `nativeEncoder()` (`:141–143`) and `render()` (`:180–191`); pipelines use `.with(pass)` / `.with(encoder)`.

**Gap to close in this pass, not later:** bind-group index assignment. `camera.ts:22` pins `$idx(0)`, but the candidate README records that the environment group index is *auto-assigned* because forcing a sparse index 3 hits 0.12.5's missing-bind-group error for anonymous gaps. Auto-assignment is per-resolution; components authored in separate files will collide once they share one root. `tg/bindIndices.ts` must pin a dense explicit index for every layout in the world, and every `tgpu.bindGroupLayout` call site reads from it.

Re-green, not new evidence.

## Compile-time negative tests (new, essential)

Precedent is thin — 3 `@ts-expect-error` in `web/tests` — so add `web/tests/typeGates/` with its own `tsconfig.typegates.json` run under `tsc --noEmit`, following `candidates/typegpu/tsconfig.json`. Minimum set, each one proving a boundary that would otherwise only fail on hardware:

1. `d.sizeOf(Camera) === 192` (`data/index.d.ts:39`) as a literal-typed assert, plus `@ts-expect-error` on a renamed/dropped `Camera` field — the schema↔`frameCamera` byte contract.
2. `@ts-expect-error` on `root.createBindGroup(cameraLayout, { camera: buf })` (wrong key) and on binding a storage buffer where a uniform is declared.
3. `@ts-expect-error` on `createRenderPipeline({ attribs })` whose vertex format contradicts the `vertexFn.In` — proves typed vertex layouts are load-bearing.
4. `@ts-expect-error` on `root.createCommandEncoder` **not** existing on stable `TgpuRoot`. This pins the 0.12.5 boundary and fails loudly (as an unused-expect-error) the day the library promotes it — the signal to revisit the encoder policy.
5. Brand `battleWorldDepth` / `battleDepthBypass` returns so a `tg/` pipeline helper rejects an inline `depthStencil` literal; `@ts-expect-error` on the literal form. Prevents silent re-divergence from `worldDepth.ts`.

Two rules are lint, not type — state that honestly: an ESLint `no-restricted-syntax` under `src/tg/**` banning `initFromDevice` outside `tg/root.ts`, and banning any `["~unstable"]` member access.
